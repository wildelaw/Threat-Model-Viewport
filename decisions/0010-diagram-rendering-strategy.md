# ADR-0010 — Diagram rendering by source format

- **Status:** Accepted
- **Date:** 2026-09-28
- **Requirements:** REQ-VIEW-003..006, REQ-SEC-004
- **Related:** `specs/07-ui.md` §7, `specs/08-security.md` §6

## Context

The two interchange formats represent diagrams in fundamentally different ways, and neither is
optional.

**OTM** represents a diagram as data: `representations` and `representationElements`, with typed
elements carrying explicit `x`/`y` coordinates, plus optional SVG or image content. Rendering it is
positioning and drawing — no parser, no third-party code.

**TML** represents a diagram as **source text**: Mermaid, Graphviz, or PlantUML, in a `diagram_type`
field. Rendering requires an actual renderer.

The renderers are not equivalent in cost:

| Format | Renderer | What it would take |
|---|---|---|
| OTM | none — coordinates | Native SVG |
| Mermaid | `mermaid` (pure JS) | A pinned CDN script, lazily loaded |
| Graphviz | `@hpcc-js/wasm` or similar | A WASM build of a large C library |
| PlantUML | Java or a rendering service | Cannot be done in-page without a server |

And all of it is untrusted input. Mermaid parses attacker-controlled text; SVG is a code-carrying
format; a Diagram tab is exactly where a hostile model would aim.

## Decision

**Render what can be rendered safely and cheaply; show source for the rest.**

| Source | Rendering |
|---|---|
| OTM coordinates | **Native SVG generated by the app.** No third-party renderer, no parser |
| Inline SVG from a model | **Sanitized** against an explicit removal list, then displayed; if sanitization cannot be completed confidently, fall back to source text |
| Mermaid | **Lazily loaded from a pinned CDN** with SRI, only when a Mermaid diagram is displayed, configured for strict security mode |
| Graphviz | **Source text** with syntax highlighting. Not rendered |
| PlantUML | **Source text**. Not rendered |
| Any image URL | Not fetched. External references are removed; `img-src` permits only `data:` and `blob:` |

Supporting rules:

- The app is **fully functional without Mermaid**. A CDN failure degrades to source text with an
  explanation, never to a broken view (REQ-VIEW-006).
- Mermaid is the **only third-party script** in the CSP, and only its origin is granted.
- The strict security mode's behaviour must be **verified against the pinned version**, not assumed —
  Mermaid has changed both `securityLevel` defaults and `htmlLabels` handling across releases, and both
  have permitted HTML injection in labels.

## Consequences

**Good**

- The most common case — an OTM model — needs no third-party renderer at all, which keeps the app's
  dependency surface at one script.
- Nothing is fetched from a URL a model supplies. A diagram cannot be used as a tracking pixel or an
  exfiltration channel.
- Every degradation path is defined, so a rendering failure is always "you can read the source"
  rather than an empty box.

**Costly**

- **A TML model with a Graphviz or PlantUML diagram is not pictured.** For a viewport whose purpose is
  reading others' models, that is a real gap. Mitigated by the fact that TML diagrams *are* source text
  by design, so the source is the authoritative artifact and the picture is a convenience.
- Mermaid is a genuine supply-chain risk and the single largest one in the app
  (`08-security.md` §7, R5). Lazy loading limits its blast radius to models that actually contain a
  Mermaid diagram.
- Hand-writing the SVG renderer for OTM coordinates means implementing layout concerns — label
  overflow, overlapping elements, z-order — that a renderer would handle. Diagrams are rendered
  **as authored**, with no auto-layout, which keeps the work bounded but means a badly-coordinated
  model looks badly coordinated.
- Sanitization is a deny-list, and deny-lists in this area have a history of gaps. The fallback to
  source text is the real safety net.

## Alternatives considered

**Render everything, including Graphviz and PlantUML.** Rejected on weight and architecture: a WASM
Graphviz build is hundreds of kilobytes in a single-file app, and PlantUML cannot be done in-page at
all without a server, which contradicts the entire design.

**Show source text for everything, render nothing.** The safest option, and seriously considered.
Rejected: OTM diagrams are coordinate data, not text — there is no "source" to show, and a viewport
that cannot display an OTM model's diagram is failing at its primary job.

**Render Mermaid inline rather than from a CDN.** Possible for a small subset, but Mermaid's bundle is
large and would ship in every exported threat model, contradicting the size reasoning in ADR-0002.

**Render SVG in a sandboxed iframe without `allow-scripts`.** Retained as an option for cases
sanitization cannot handle, but not the default, because an iframe per diagram is heavy and complicates
the layout and accessibility story. Sanitize-and-inline is the default; iframe is the escape hatch.
